# Run your first Linux guest

Boot the packaged Linux userspace and execute a program inside it. This uses the high-level guest API; you do not need to assemble devices or a root filesystem.

## Requirements

The guest runs entirely inside the host JavaScript process. Before installing anything, check that the runtime can provide the primitives needed by the WebAssembly kernel.

- Node.js 22 or a modern browser.
- A cross-origin isolated page when running in a browser.[^coop-coep]
- WebAssembly threads and JavaScript Web Worker support.

[^coop-coep]: Serve the page with `Cross-Origin-Opener-Policy: same-origin` and `Cross-Origin-Embedder-Policy: require-corp` so the kernel can use shared memory.

Node does not need elevated privileges, KVM, or a system-wide virtual machine manager. In a browser, `crossOriginIsolated` should be `true` before you create a guest.

## Install the packages

The guest package provides the convenient process and filesystem API. It uses the kernel package as its host runtime, so install the two packages together.

```
npm install @tombl/linux @tombl/linux-guest
```

Both packages are ESM-only. The examples below use top-level `await`; put them in an ES module or inside an async function if your application does not already use modules.

## Boot Linux and run a program

A guest owns its kernel, userspace, and processes. Keep the returned object for as long as anything inside the guest is running.

### Start the guest

`spawnGuest()` loads the packaged kernel, initramfs, and root filesystem, then waits until the guest agent is ready. The promise resolves only after commands can run.

```javascript
import { spawnGuest } from "@tombl/linux-guest";

const guest = await spawnGuest();
const child = await guest.exec(["/bin/uname", "-a"]);

console.log(await new Response(child.stdout).text());
```

### Work with files

The guest filesystem starts from the packaged root image. Writes are private to this guest and last until it is closed. Host strings and byte arrays can be copied into it directly.

```javascript
await guest.writeFile("/tmp/message", "hello from the host\n");

const child = await guest.exec(["/bin/cat", "/tmp/message"]);
console.log(await new Response(child.stdout).text());
```

Process output is exposed as a web `ReadableStream`. This keeps the same API in Node and browsers and lets callers consume long-running output without buffering all of it.

### Stop the guest

Close the guest when the application no longer needs it. Closing terminates its remaining processes and releases the worker and WebAssembly memory owned by the virtual machine.

```javascript
await guest.close();
```

## Expected output

The first example prints the kernel identity reported from inside the guest:

```
Linux localhost 6.1.0-wasm #1 SMP wasm32 GNU/Linux
```

You now have a running guest. The same object exposes its process, filesystem, and networking APIs, so later operations do not need to boot another kernel.

## Next steps

Try passing environment variables and a working directory to `exec()`, or mount files supplied by the host before starting a program. For services, keep the process handle and stream stdout while the guest continues to run.

The how-to guides build on this guest and cover bidirectional file transfer, process signals, and networking between two isolated Linux instances.
