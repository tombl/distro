# Troubleshooting

## `Linux.create()` fails in the browser with an error about `SharedArrayBuffer` or shared memory

The page is not cross-origin isolated. Evaluate `crossOriginIsolated` in its console. If it is
`false`, the document was served without the headers in
[Hosting](/hosting/#the-headers). Check them in the network panel, on the document itself, not
on its scripts.

## `SecurityError` when the machine boots

The kernel tried to start a worker from another origin. This happens when an import map points
the packages at a CDN. Serve them from the page's origin.

## `... did not return a disk image: got text/html`

The image URL served a web page instead of an image, usually a dev server's fallback for a path
that does not exist. Check the path relative to the page, and that the image is in the build
output.

## `mounting m0 (...) at /: ...`

`Linux.create()` rejected with a `GuestBootError`, because an entry of the mount table failed to
mount. Its `kernelLog` is the end of the guest kernel's log, which usually says why. A source
that is not a filesystem fails with `EINVAL` from every type the guest tried. An ext4 image that
was not unmounted cleanly, because its machine was killed, fails in mode `"ro"` or `"overlay"`
with `EROFS`, because its journal needs recovery, which read-only storage cannot have. Mount it
in mode `"rw"` once to recover it.

## `Linux.create() needs an image`

`image` has no default. Pass `rootImage()` from `lowland/image` for the bundled image, or a
source of your own.

## The machine fails during boot and nothing explains why

Add `bootConsole(output)` from `lowland/machine` to `plugins` to see the kernel's boot
messages. A kernel panic resolves `linux.exited` to `{ reason: "crash", error }`, with a
`MachinePanicError` as the error.

## The Node.js script never exits

A running machine keeps the event loop alive. Call `linux.shutdown()`, or declare it with
`await using`.

## `shutdown()` resolves to `{ reason: "kill" }`

The guest did not power off before the timeout, so the machine was killed, and writes it had not
flushed are lost. A program stuck in a loop without system calls cannot be stopped, and holds
up the shutdown. Without the guest agent, the image's init may not handle the power signals. See
[The layers beneath](/layers/#machines-without-the-guest-agent).

## A timeout fired, but the program is still running

The program is in a loop that makes no system calls, so it cannot receive signals, `SIGKILL`
included. Kill the machine. See
[What runs, and what doesn't](/what-runs/#busy-loops-and-spinners).

## Everything in the machine stopped

Usually the same cause: with one virtual CPU, a task in a loop without system calls keeps the
CPU, and nothing else in the machine runs. A spin-wait in a program waiting for another thread
does the same. Give the machine more CPUs, or fix the loop to yield.

## `fork` or `mmap` is undeclared when compiling

They do not exist in the guest. See [What runs, and what doesn't](/what-runs/).

## A program installed to `/usr/local/bin` is "not found"

The guest agent's `PATH` is `/bin:/usr/bin:/sbin:/usr/sbin`. Configure with `--prefix=/usr`, or
run it by full path.

## `wget https://...` fails in the browser

`hostFetchNetwork()` reads plain HTTP requests to find their destination, and TLS from the guest
hides them. Use `http://` URLs in the guest. The browser's `fetch()` adds TLS on the way out.

## Requests from the guest fail in the browser, but work in Node.js

The browser's cross-origin rules apply to the `fetch()` each request turns into. The site does
not send CORS headers. Route the request through a proxy you run, in the `fetch` function you
pass to `hostFetchNetwork()`.

## Connecting to a guest server is refused right after starting it

`spawn()` resolves once the program has started, not once it is listening. Retry the connection
briefly.

## Spawning many programs fails with `ENOMEM` in Safari

Safari frees the memory of a finished process about a second after it exits. A guest that starts
many short-lived programs in quick succession can run out of address space before then. Start
fewer processes, or slow the rate.

## Files written to a disk are missing after reload

The guest kernel had not written them yet when the machine was killed or the tab closed. Shut
the machine down instead of killing it, call `linux.fs.sync()` after writes that matter, and mount
with `options: "sync"` if the tab may close at any time. See
[Files and storage](/files-and-storage/#dont-lose-writes).

## `NoModificationAllowedError` when attaching an OPFS disk

Another tab has the same file open. Only one sync access handle can be open at a time. See
[Files and storage](/files-and-storage/#one-tab-at-a-time).

## The Vite dev server fails to boot the machine, but the build works

Vite 7 pre-bundles dependencies and breaks their asset URLs. Exclude the packages in
`optimizeDeps.exclude`, as in [Hosting](/hosting/#bundlers), or use Vite 8.
