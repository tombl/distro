# Share a host directory

A shared directory lets programs in the guest read and write host files directly, without
copying them in and out. It takes two steps:

1. Attach a filesystem device when the machine boots. The device is backed by a host
   directory and has a tag.
2. Mount the device by its tag inside the guest.

## In Node.js

`NodeFS` serves a directory from the host filesystem:

```ts
import { bootMachine, fileSystemDevice } from "@lowland/kernel";
import { guestAgent } from "@lowland/guest";
import { NodeFS } from "@lowland/guest/node";

const shared = fileSystemDevice(new NodeFS("./shared"), { tag: "host" });
const guest = guestAgent();
await using machine = await bootMachine({
  cpus: 1,
  plugins: [root, guest, shared],
});

await guest.fs.mkdir("/tmp/host");
await guest.mount("host", "/tmp/host", { type: "virtiofs" });
```

`root` is the root filesystem device from the
[`@lowland/guest` usage example](/reference/guest/#usage). Files under `./shared` are now
visible at `/tmp/host`, and files the guest writes there appear in `./shared`.

The mount point must be in a writable location such as `/tmp`, unless the machine boots with
a writable root.

## In a browser

`BrowserFS` serves a `FileSystemDirectoryHandle`. That can be a folder the user picks, or the
origin private file system:

```ts
import { BrowserFS } from "@lowland/guest/browser";

const directory = await navigator.storage.getDirectory();
const shared = fileSystemDevice(new BrowserFS(directory), { tag: "host" });
```

Mount it the same way as in Node.js. The browser file system API has no Unix permissions,
ownership, or atomic rename, so `BrowserFS` emulates them. The
[`BrowserFS` reference](/reference/guest/#BrowserFS) describes what can go wrong if an
operation fails partway.

## Share a directory read-only

Mounting with the read-only flag does not stop the guest kernel from sending write requests
to the device. To make a directory read-only, configure the backend:

```ts
new NodeFS("./shared", { readOnly: true });
```

Writes from the guest then fail with code `"EROFS"`.

## Directories that change on the host

By default the guest caches file metadata and directory listings for one second. If other
programs on the host change the directory while the guest is running, turn the cache off:

```ts
fileSystemDevice(new NodeFS("./shared"), { tag: "host", cache: false });
```

This affects metadata and names only. File contents the guest has already read can still be
cached by the guest.

## Choosing a directory

Share a directory your application owns. `NodeFS` keeps paths inside the shared directory,
but it cannot guarantee that while another host process is moving things around inside it.
The [`NodeFS` reference](/reference/guest/#NodeFS) has the details.

## Unmount

```ts
await guest.unmount("/tmp/host");
```

The device stays attached until the machine closes. Devices cannot be added after boot, so
attach every directory you might share when the machine starts.
