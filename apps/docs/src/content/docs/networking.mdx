# Networking

A machine has no network unless you give it one. When you do, the network is a JavaScript
object in your process, and every connection that leaves it goes through a function you wrote.
That function is the whole policy. There is no NAT and no firewall to configure.

## A switch in your process

```js
import { createNetwork, guestAgent } from "lowland/guest";

const network = createNetwork({ connectTcp, resolveDns });
const guest = guestAgent({ mounts: [rootImage()] });
await using machine = await bootMachine({
  cpus: 1,
  plugins: [guest, network.attach(guest)],
});
```

`createNetwork()` creates an Ethernet switch. `network.attach(guest)` gives the machine a virtio
network card, `eth0` in the guest, plugged into that switch. The switch learns MAC addresses and
floods broadcasts like a hardware one, so guests on the same network can use any protocol over
Ethernet between themselves. All of them run in the same process as the switch.

A network is the subnet `192.0.2.0/24`, a range reserved for documentation, so it does not
collide with real networks. Attachments get `192.0.2.2`, `192.0.2.3` and so on, in order, and
addresses are not reused. `attachment.address` reports the address. Once the guest agent is
ready, the network configures `eth0` statically. There is no DHCP.

`192.0.2.1` is the gateway. It is not a guest but a small TCP/IP stack inside the network
object. It answers ARP, TCP and DNS, but not ICMP, so pinging it gets no reply while pinging
another guest works.

## Leaving the network

The gateway does not route packets anywhere. When a guest connects to an address outside the
subnet, the gateway terminates the guest's TCP connection itself and calls your `connectTcp`
once for it, with a `TcpSession`:

- `session.target` is the address and port the guest connected to. It is always an IP address,
  because the guest looked the name up first. Connections to `192.0.2.1` itself arrive as
  `127.0.0.1`.
- `session.readable` and `session.writable` carry the bytes in each direction.
- `session.signal` aborts when the connection ends.

The guest's connection is not accepted until your function first reads or writes. If it throws
before then, the guest sees the connection refused, so you can check `session.target` before
the guest learns anything.

DNS queries to the gateway reach `resolveDns(hostname)`, which returns IPv4 addresses. Other UDP
leaving the subnet is dropped. There is no hook for it.

## In Node.js

Node.js can open real sockets, so the guest gets real TCP, TLS included:

```js
import { resolve4 } from "node:dns/promises";
import { once } from "node:events";
import { createConnection } from "node:net";
import { Duplex } from "node:stream";

const network = createNetwork({
  async connectTcp(session) {
    const socket = createConnection({
      host: session.target.hostname,
      port: session.target.port,
      signal: session.signal,
    });
    await once(socket, "connect");
    const streams = Duplex.toWeb(socket);
    await Promise.all([
      session.readable.pipeTo(streams.writable),
      streams.readable.pipeTo(session.writable),
    ]);
  },
  resolveDns: resolve4,
});
```

Programs that half-close a connection, such as an HTTP client that shuts down its write side
and waits for the reply, need Node.js 24.20 or 26.7 or later. Earlier versions of
`Duplex.toWeb()` drop the reply.

## In a browser

A page cannot open sockets, so `hostFetchNetwork()` turns guest HTTP into `fetch()` calls:

```js
import { createNetwork, hostFetchNetwork } from "lowland/guest";

const network = createNetwork(hostFetchNetwork({ fetch: (request) => fetch(request) }));
```

Its `resolveDns` answers every name with the same placeholder address, because a page cannot
do DNS lookups. Its `connectTcp` reads one HTTP request from each connection, takes the
destination from the `Host` header, and sends it as an HTTPS `fetch()`. That has consequences:

- Guest programs must use plain `http://` URLs. The browser adds TLS on the way out. A program
  that speaks TLS itself, such as `wget https://...` or `apk` with an HTTPS repository, sends
  bytes the gateway cannot read, and fails.
- The page's cross-origin rules apply. Most sites don't send CORS headers, so the browser hides
  their responses. Point the `fetch` function you pass at a proxy you run to reach them.
- Each connection carries one request.

The default image's apk repository uses `http://`, so `apk add` works through this.

## The example: no network, or an allow-list

The example service runs untrusted snippets, so by default it attaches no network card at all.
To let snippets fetch from one API and nothing else:

```js
const allowed = new Set(await resolve4("api.example.com"));

const network = createNetwork({
  async connectTcp(session) {
    if (!allowed.has(session.target.hostname) || session.target.port !== 443) {
      throw new Error("blocked");
    }
    // ...connect as above...
  },
  resolveDns: async (name) => (name === "api.example.com" ? [...allowed] : []),
});
```

Use one network per snippet. Guests on the same network can reach each other directly, without
passing through `connectTcp`.

## Connecting into a guest

`attachment.connect({ port })` opens a TCP connection from JavaScript to a port in that guest,
and `network.connect()` does the same by address. The guest sees an ordinary connection from
`192.0.2.1`. The call resolves when the guest accepts and rejects if nothing is listening. A
server started with `exec()` may not be listening yet when `exec()` resolves, so retry.

For HTTP, `guestFetchHandler()` wraps this in the shape of `fetch`, taking a `Request` and
returning a `Response`:

```js
import { guestFetchHandler } from "lowland/guest";

await guest.exec(["httpd", "-f", "-p", "8080", "-h", "/www"]);
const handler = guestFetchHandler(attachment, { port: 8080 });

const response = await handler(new Request("http://my-app.example/"));
```

Each call is one connection, with streamed bodies. The guest sees the `Host` from the request
URL, so links it generates point where the user is. In Node.js, the handler plugs into any
server framework that takes fetch-style handlers. In a browser, a service worker can forward
navigations to the page that owns the machine. The low.land demo does this to show guest web
servers in a tab. Its code is in
[`packages/bridge-site`](https://github.com/tombl/distro/tree/main/packages/bridge-site), and is
a starting point rather than a supported package.

## Several guests

Attach several guests to one network and they reach each other by address:

```js
const network = createNetwork({ connectTcp, resolveDns });
const serverNet = network.attach(server);
const clientNet = network.attach(client);
// boot both machines with their attachments...

await client.run(["wget", "-qO-", `http://${serverNet.address}:8080/`]);
```

`network.close()` closes every connection and detaches every guest.
